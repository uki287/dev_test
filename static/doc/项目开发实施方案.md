## 1. 目的与范围

- **目的**：将已评审的四份文档翻译为可执行的开发排期与模块拆分，明确各阶段交付物、验收标准与协作方式，作为后续编码阶段的执行基线。

  - 部署（Docker + Nginx）、种子与备份。
- **不在本方案范围**：UI 设计稿重做（已完成）、企业真实素材提供（见 §8）、需求范围变更（走变更评审）。

## 5. 开发阶段划分与任务明细

> 设计阶段（PRD/UIUX 原型）已完成，本期从 M2（基础框架）起。阶段与 PRD §10 里程碑对齐，阶段内任务拆到可验证粒度。每个阶段结束必须过验收再进下一阶段。

### Phase A — 工程骨架（对应 M2，约 1 周）

**目标**：三应用可启动、可联调，Mock 数据层就绪。

- [ ] 初始化单仓库：`frontend/`、`admin/`、`backend/` 三个 Vite/FastAPI 工程；
- [ ] 设计 token 落地：
  - 前台 `tailwind.config.js` 映射 UI/UX §3 色板（ink/gold/cream/line）、字体（Playfair Display + Noto Serif SC / Inter + PingFang SC）、圆角（16/8/6）、阴影（shadow-gold/card）；
  - 后台 AntD `ConfigProvider` 主题：主色 `#B98A2F`、布局底 `#FAF8F4`、菜单黑底金字；
- [ ] Vite 代理：`/api` → `http://localhost:8000`；环境变量 `VITE_API_BASE`、`VITE_USE_MOCK`；
- [ ] 后端骨架：`core/config.py`（pydantic-settings：DB_URL/JWT_SECRET/UPLOAD_DIR/CORS_ORIGINS/REDIS_URL）、`core/security.py`、`core/deps.py`、`core/exception.py`；统一响应体 `ApiResp{code,message,data}`；
- [ ] 数据库骨架：`db/base.py`（Base + ActivateMixin/AuditMixin/SoftDeleteMixin，字段对齐数据库设计 §4.0）、`db/session.py`、Alembic `init`；
- [ ] Mock 层：`frontend/src/mock`、`admin/src/mock` 复用原型 `DEFAULT_STORE` 字段名（banners/series/products/news/jobs/users/roles/logs/appointments/messages/settings），经 `VITE_USE_MOCK` 开关切换；
- [ ] 前端 API 客户端封装（axios 实例 + 拦截器 + 401 跳登录 + `{code,data,message}` 解包）。

**产出**：三应用可 `dev` 启动；Mock 下前台可浏览、后台可登录（默认账号见种子）。
**验收**：`npm run dev` / `uvicorn` 均起得来；Mock 数据驱动首页与后台列表正常渲染。

### Phase B — 数据库 + 鉴权 + 基础设施（后端，约 1.5 周）

**目标**：19 张表落地、鉴权 RBAC 可用、Redis 接入。

- [ ] SQLAlchemy 模型：按数据库设计文档 §4 逐表定义（含公共字段、软删、JSON 列、软外键），模型继承 Mixin；
- [ ] 迁移：`alembic revision` 生成迁移并核对 JSON/JSONB；开发期 `Base.metadata.create_all()` 快速建表；
- [ ] 种子 `seed.py`：默认超级管理员（`admin`，`forcePwd=true`）、三预置角色（`super_admin`/`content_editor`/`operator`）、权限树（18 个权限码）、示例 banner(4)/series(3)/product_category(5)/product(12)/news(4)/job(5)/company_info/about_info/about_timeline/system_settings(sliderInterval=4)、脱敏示例 appointment(6)/message(3)；公共审计字段以 `admin` 填充；
- [ ] 认证模块（`/auth`）：`GET /captcha`（图形验证码，Redis 缓存 token+答案，60s 失效）、`POST /login`（bcrypt 校验 + 失败 5 次锁 15 分钟，Redis 记录 `fail_count`/`locked_until`）、`POST /logout`、`GET /me`、`POST /refresh`、`POST /reset-password`（强制改密 L-04）；
- [ ] JWT：8h 有效期、续期、登出黑名单（或客户端清除 + 服务端黑名单）；
- [ ] RBAC：`require_perm(code)` 依赖取单一角色权限集合、支持 `xxx:*` 通配；菜单按权限码过滤（L-05）；
- [ ] Redis 接入（D2）：内容接口缓存（banner/series/about 60s）、限流（登录/预约/留言 IP 滑动窗口，默认 10 次/分）；
- [ ] 上传：`POST /admin/upload`（白名单 jpg/png/webp/gif，≤5MB，UUID 重命名，落 `uploads/`，Nginx 不执行）；
- [ ] 统一异常 → `{code,message}`；操作日志中间件（关键写操作落 `operation_log`）；PV 统计中间件（写 `visit_stat` 日聚合）。

**产出**：后端可注册/登录/鉴权；19 张表 + 种子就绪；Redis 缓存与限流生效。
**验收**：Swagger `/docs` 可跑通登录拿到 JWT；受保护接口无 token 返 401、越权返 403；限流触发返 429；上传返回 UUID 路径。

## 6. 各层关键实现要点（约束摘要）

- **后端分层**：Router（校验/装配）→ Service（业务/权限）→ Model → DB；依赖注入 `get_db`/`get_current_user`/`require_perm`；统一异常 → `{code,message}`。
- **接口约定**：前缀 `/api/v1`；分页 `?page&page_size`（上限 50）；公开接口（前台只读 GET、验证码、登录、预约/留言提交）；受保护接口需 `Bearer JWT`；错误码 0/40100/40300/40001/42900/50000（Dev §6.2）。
- **权限码**：`banner:*` `series:*` `product:*` `news:*` `job:*` `about:*` `appointment:view|handle|export` `message:view|handle|export` `user:*` `role:*` `log:view` `stat:view` `setting:*` `upload:*`（Dev §7.2）；预置角色见 §3.2。
- **安全合规**：bcrypt 密码；登录失败 5 次锁 15 分（Redis）；验证码服务端缓存；IP 限流；富文本 bleach 清洗；上传白名单+UUID+防穿越；隐私最小化（手机号列表脱敏、详情需权、日志不存明文）；全站 HTTPS；统一异常不泄露堆栈。
- **前台技术**：设计 token 严格按 UI/UX §3；路由对应 PRD §5.1 IA；Zustand 管导航抽屉/下拉单例/站点配置；图片懒加载 + 首屏 Banner 预加载；代码分割 `lazy()`；字体 `display=swap`。
